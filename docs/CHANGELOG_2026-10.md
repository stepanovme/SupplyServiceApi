# Список изменений бэкенда supply (октябрь 2026)

Все эндпоинты — под префиксом `/apisup/supply`. SQL-миграции лежат в `cmd/sql/` и **уже применены** к базе.
Что нужно сделать при выкладке: см. раздел «Выкладка» в конце.

## 1. Банковские выписки и оплаты

**Интеграции с банками**
- Таблицы и CRUD `settings_api_bank` (несколько интеграций, поле `name`) и счета интеграции; поддержаны Сбербанк и Т-Банк.
- Загрузка выписок: из API Сбербанка (за день или период, фоновая задача), из API Т-Банка, из Excel (Альфа-Банк). Фильтры по счёту и банку (`account_number`, `bank_type`).
- Таблица `extract_items`: добавлены `account_number`, `bank_type`, `external_id`; дедупликация по собственным идентификаторам банка. Для Альфы ключ теперь составной (дата, направление, сумма, хеш назначения, счётчик `#n`) — раньше терялись реальные операции с одинаковым номером документа.
- Очистка дублей-близнецов в `extract_items` (с резервной копией в `cmd/sql/*backup*.json`). Миграция ключей Альфы: `cmd/migrate_alfabank_external_ids.py`.
- Исправлена ошибка парсера Excel (`payee_kpp` при первой операции-кредите).

**Привязки операций**
- Договоры: автосопоставление по назначению платежа (ИИ) и ручные привязки; в `/contracts` — платежи и `paid_sum`.
- Бизнес-карты: ручное создание и загрузка из Сбербанка, сопоставление по последним 4 цифрам, расходы по картам (с учётом возвратов, по объектам, «по всем»), `GET /business-cards/my` (мои карты), операции по объекту.
- Платежи по счетам: `invoice-payment-extracts` (match / match-all, ручная привязка, уведомления как у ручного платежа). Одна операция выписки теперь может быть привязана **к нескольким** платежам с долями (`POST /bulk`, `PATCH`).
- Операции выписки привязываются к объекту: `object_id`, `POST /extract-items/set-object`, фильтры `object_id` / `object_missing`, `GET /extract-items/by-object/{object_id}` (без операций по картам). В ответах — `invoice_payments` (список) и прежнее `invoice_payment`.
- В платежах счетов: `has_extract`, `extracts`; `GET /invoices/my/payments` получил `provider_logo_url`, `payer_logo_url`, `object_levels_id`, `object_type`, `project_name`.

## 2. Распознавание документов (Mistral)
- Единая цепочка: быстрая модель (`ministral-3b-2512`) → `pixtral-12b-latest`; OCR-модель — по желанию. Datalab удалён.
- Отдельные ключи по функциям: `MISTRAL_OBJECT_NAME_API_KEY`, `MISTRAL_CONTRACT_EXTRACT_API_KEY`, `MISTRAL_INVOICE_EXTRACT_API_KEY`, `MISTRAL_RECEIPT_CATEGORY_API_KEY`.
- Обработка лимитов Mistral (повторы с задержкой), подсказки названий объектов (`object-name-suggestions`).

## 3. Объекты
- Группы объектов (`object-groups`, таблицы в `reference_service`): главный объект + вложенные, CRUD, `by-object`.
- Договоры и счета «по объекту» (включая приватные счета), миграции данных (`object_levels_id` → объект, права `view_invoice`).
- Расходы по объектам (`object-expenditures`), поступления по договорам (`receipt-contracts`).
- **Несколько объектов у акта:** таблица `act_objects` (перенесены объекты всех 93 актов), `GET/POST /acts/{id}/objects`, `DELETE /acts/{id}/objects/{obj_id}`, список `objects` в ответах. У договоров и писем это уже было (`/contract-objects`, `/letter-objects`); теперь `objects` можно передать сразу в теле `POST /contracts`, `/letters`, `/acts`.

## 4. Договоры, акты, документы
- `GET /acts/by-contract/{contract_id}` — акты договора (как в `GET /acts` + данные связи).
- `documents-links`: у документов типа `act` добавлена расшифровка (`full_name`, тип, номер, дата).
- Договоры: сумма выполненных работ по актам `acts_sum` (КС-2 и КС-3 с одной суммой — один раз), `debt_sum` (задолженность), `receivable_sum` (дебиторская), `acts`, `acts_count`, `acts_counted` — в списках и карточке. Для договоров типа «Поставщик» дебиторской нет, а задолженность есть только когда есть акты и нет оплат.
- `documents-list`: Заказчик и Подрядчик (`customer_id`, `contractor_id`, названия в ответе; загрузка и `PATCH`). Доступ «по контрагенту» теперь учитывает и их.

## 5. Чеки (`purchase-receipts`)
**Добавление:** вручную, по QR (`from-qr`), по фото (`from-photo`; фото сохраняется как файл чека). Данные чека — с proverkacheka.com.
- Три ключа (`PROVERKACHEKA_TOKEN`, `_2`, `_3`); переключение при настоящем исчерпании квоты. Коды 3 и 4 сервиса — ограничения по **чеку**, не по ключу: ключи не меняются, отказ запоминается на время; тайм-аут 75 с; защита от параллельных дублей одного QR.
- Защита от повторов по фискальным реквизитам (`409`).

**Данные и права:** позиции, объект, бизнес-карта, **способ оплаты** (`business_card` / `cash` / `credit_card`), **от кого / для кого** (пользователи), **хештеги** (`GET /hashtags`, фильтр), **комментарии** (переписка), заметка владельца `comment`, **логотип продавца** (`seller_logo_url`), несколько фото, доступ другим пользователям (`view` / `edit`).
- Список: по умолчанию **по дате добавления, сверху новые** (`sort_by`, `order`), фильтры `payment_method`, `hashtag`, `from_user_id`, `for_user_id`, `category_id`, `object_id`, даты.
- `GET /purchase-receipts/objects` — объекты с моими чеками и их количеством; `by-object/{id}` со сводкой (в т.ч. по способам оплаты).
- Массовые операции: `bulk-update` (объект, карта, способ оплаты, категории, хештеги, от кого/для кого), `bulk-delete`, `bulk-share`, `auto-categorize`.

**Категории чеков** (`receipt-categories`): отдельная таблица с цветами; 17 стандартных (для всех) и личные; CRUD (стандартные меняет администратор); удаление используемой категории — только с `force=true`.
**ИИ-категории:** после добавления чека Mistral подбирает до 3 категорий по позициям из доступных пользователю.
**Логотипы продавцов** (`receipt-seller-logos`): по ИНН, ссылкой или файлом (png/jpg/webp/gif), список «без логотипа», только для администратора.

## 6. Исправления
- `GET /invoices/my/payments?paid=…` падал с 500 (не был импортирован `datetime`).
- `warehouse_list`: количество и цена ограничены допустимым диапазоном колонки — вместо 500 приходит `422` (см. «Открытые вопросы»).
- Парсер Excel Альфы, ошибки `Decimal`/`float` в суммах по картам и договорам.

## Выкладка
1. Перезапуск API (при `reload=True` он подхватывает файлы сам).
2. `.env` (шаблон — `.env.example`): `PROVERKACHEKA_TOKEN`, `_2`, `_3`; `MISTRAL_RECEIPT_CATEGORY_API_KEY` (+ `RECEIPT_CATEGORY_MODEL` по желанию); `SUPPLY_RECEIPT_FILES_DIR` / `_URL`; `SUPPLY_RECEIPT_LOGOS_DIR` / `_URL`; ключи Mistral по функциям.
3. Папки с файлами чеков и логотипов должны быть доступны на запись процессу API и (для прямых ссылок) опубликованы веб-сервером.

## Что изменилось в поведении существующих эндпоинтов
- Список чеков теперь сортируется по дате добавления (раньше — по дате чека).
- `POST /contracts` с `objects` возвращает полный вид договора.
- Прикрепление объекта через `PATCH /acts/{id}` добавляет его в список объектов, а не заменяет остальные.
- Доступ к `documents-list` «по контрагенту» шире: учитывает заказчика и подрядчика.
- `GET /extract-items`: поле `invoice_payment` сохранено, добавлен список `invoice_payments`.
- Справочник `/warehouse-categories` — без изменений (цвета для него не вводились).
