# Обмен документами между сайтами

Это внутренний обмен файлами и статусами; он не накладывает электронную подпись и не подключён к оператору юридически значимого ЭДО. Принятие означает решение пользователя в приложении.

## Настройка

Общий журнал находится в БД снабжения сайта, указанного в `EDO_HUB_TENANT`. Не меняйте эту переменную без переноса всех таблиц `edo_*`: в них хранятся постоянные идентификаторы сайтов, приглашения, история, документы и копии файлов. Команда `python -m cmd.migrate_edo` создаёт недостающие таблицы и регистрирует новые сайты. Повторный запуск сохраняет существующие идентификаторы.

В `.env` перечислите ID назначенных пользователей через запятую:

```dotenv
EDO_HUB_TENANT=FIRST
TENANT_FIRST_EDO_USERS=user-id-1,user-id-2
TENANT_EFIMOV_EDO_USERS=user-id-3
EDO_MAX_DOCUMENT_BYTES=8388608
```

`*` разрешает доступ всем авторизованным пользователям сайта; пустой список запрещает доступ всем. Чтобы ограничить доступ, вместо `*` перечислите ID разрешённых пользователей. После изменения `.env` перезапустите backend. Каждый запрос проверяет сессию сайта и наличие пользователя в его списке. При отправке пользователь также должен быть создателем исходного документа или назначенным в его ролях. Права на обмен назначаются отдельно от прав обычных реестров.

## Методы

Все пути ниже начинаются с `/apisup/supply/edo` на внешнем прокси (в приложении — `/api/supply/edo`):

- `GET /me` — получить свой `participant_id`. Передайте его контрагенту.
- `POST /relationships` с `{"participant_id":"UUID"}` — отправить приглашение.
- `GET /relationships` — входящие и исходящие приглашения и их статусы.
- `POST /relationships/{id}/decision` с `{"decision":"accept"}` или `{"decision":"reject"}` — принять или отклонить входящее приглашение. Повторно пригласить можно после отказа.
- `POST /documents` с телом ниже — отправить снимок документа и выбранных файлов стороне с принятой связью. Доступные типы — `contract`, `act`, `upd` (реестр УПД).
- `GET /documents?direction=incoming` или `direction=outgoing` — последние 200 документов. Для списка файлов нужно открыть конкретный документ.
- `GET /documents/{id}` — сведения, снимок и список файлов.
- `GET /documents/{id}/files/{file_id}` — скачать файл.
- `POST /documents/{id}/decision` с `{"decision":"accept","comment":"..."}` либо `reject` — решение получателя. Комментарий необязателен. Повторно изменить решение нельзя.
- `GET /documents/{id}/history` — история отправки и решения.

```json
{
  "participant_id": "UUID-получателя",
  "document_type": "contract",
  "document_id": 123,
  "file_ids": ["UUID-файла"]
}
```

При отправке копируются выбранные файлы и основные поля: номер, дата, сумма, наименование, внутренний номер, даты действия и комментарий — если они есть у документа. `file_ids` обязательны; доступно до 20 файлов и по умолчанию до 8 МиБ суммарно. Файлы и поля фиксируются на момент отправки: последующее изменение или удаление оригинала их не меняет. В получающем сайте документ доступен во входящих ЭДО и не создаётся автоматически в обычном реестре. Статусы оригинала также не меняются.
