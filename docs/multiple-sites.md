# Несколько сайтов

В `.env` задайте `TENANTS` по примеру из `.env.example`. Для каждого домена нужны имена баз авторизации, снабжения и справочников; для функций склада также задайте `WAREHOUSE_DB_NAME`. Общие `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD` можно переопределить в настройках отдельного сайта. Перезапустите приложение после изменения `.env`.

Для браузерных запросов сайт определяется по `Origin`, для запросов без `Origin` — по `Host`. Неизвестный сайт отклоняется. Прокси должен передавать исходные заголовки, а прямые запросы и интеграции без Origin должны использовать настроенный Host. Если все сайты обращаются к одному API-домену, запросы без Origin необходимо маршрутизировать через отдельные домены API или добавить доверенную маршрутизацию на прокси. Origin и Host могут быть подделаны: доступ к данным должен проверяться авторизацией в соответствующей базе; нельзя использовать домен как единственную защиту.

Для команд из `cmd/` задайте переменную окружения `TENANT_CLI_SITE` с именем сайта: например, `TENANT_CLI_SITE=FIRST python -m cmd.ИМЯ_СКРИПТА`. Перед запуском проверьте назначение команды и выбранные базы. SQL-файлы с межбазовыми ссылками необходимо сначала подготовить: `python cmd/render_sql.py cmd/sql/business_cards.sql --site supply.st29.ru > /tmp/business_cards.sql`. Затем проверьте результат и выполните его в базе снабжения выбранного сайта. В односайтовом режиме параметр `--site` не нужен.

Базы и их схемы должны быть созданы и мигрированы заранее. Файловое хранилище и внешние интеграции используют общие настройки; их изоляция между сайтами этим изменением не обеспечивается.

Имя cookie задаётся отдельно для каждого сайта: `TENANT_FIRST_COOKIE_NAME=session`, `TENANT_EFIMOV_COOKIE_NAME=session_efimov`. Если имя не задано, используется `session`.
